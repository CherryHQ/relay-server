direct 优先 → 安全 Relay → 可选 P2P
1

先尝试现有 direct

App 使用可达地址；直连成功即交付业务。不可达时，按原样 v1 完成 Relay 会合与 ready。

2

Relay 上完成 Noise、hello 和设备认证

新桌面在 hello 声明可选 connectionP2PVersion。任一端不支持或未启用，继续 Relay；服务器无需声明 P2P 能力。

3

两端通过加密通道协商

App 发 offer，桌面发 answer；SDP / ICE 作为加密控制消息交换，绑定父连接、两端身份、代际和一次性关联值。两端直接访问配置的 STUN。

Relay 看不到信令明文；通用 P2P 子入口接受注入的信令收发接口。

4

候选 DataChannel 重新建立 Noise 与授权

新 MessageStream 固定同一端点身份，再次 hello、认证并校验关联值。候选只开放握手、授权和切换控制，尚不接受业务 RPC。

5

产品 owner 确认唯一业务路径

App 发起切换，桌面串行校验并确认；提交后旧路径停止业务，双方完成确认才交付新通道。

P2P 提交成功
交付新安全通道
→ 释放本次 Relay 数据连接
→ 保留桌面 listener
提交前连通性失败
清理候选
→ 交付已认证的 Relay
→ 不重复会合

确认结果不确定：关闭本轮并重连。身份不符或授权撤销：终止，不能用回退绕过。

6

业务与恢复保持原有 owner

一次只交付一条业务路径。已运行的 RPC / 订阅不做热迁移；真正断线重连、新建 Noise，再恢复业务状态，不重放命令。已建立的 P2P 不依赖 Relay 持续在线。

原有 15 秒预算包含两次 Noise。有 Relay 时 direct 最多 5 秒；P2P 尝试初始最多 3 秒，覆盖 ICE、新 Noise / 授权和切换。预留至少 1 秒回退与清理，不够就交付 Relay；参数待实测。

性能边界

二进制 + 有界背压

现有 WSS DATA 最大 64 KiB；P2P 初始拟 ≤ 16 KiB / 消息。分别限制应用队列、桥接在途和原生缓冲，计入旧流与候选并存的峰值。

目标是减少中继流量

首连要支付 Relay 引导和额外 Noise 的成本。真实验证 1 MiB、慢读、换网、后台与功耗；RN 桥可能使用 Base64，不承诺零拷贝或更快建连。

状态放在哪里

归属 内容 保存方式
桌面 身份、配对 / grants、Relay 入口密钥、业务任务和结果 端侧持久存储
App 本机身份、配对、已验证的桌面 / Relay 地址 端侧持久存储
端侧 P2P · 计划 协商代际、关联值、候选和暂存信令；开关与 STUN 地址 协商只在内存；配置可持久保存
Bun runtime 在线映射、socket、临时票据、session、资源计数 有界内存；重启失效
DO runtime 上述连接状态的最小恢复快照；角色、代际、期限、计数 socket attachment + alarm；无业务数据库
账号后端 · 可选 账号凭证、组织 / 权益、后台认证 独立后端自己的数据库
通知网关 · 可选 推送配置、必要时的通知 outbox 独立服务；不放 Relay
休眠恢复 ≠ 消息持久化。
DO 保留 socket，并恢复继续转发所需的最小状态；加密信令和其他数据走相同路径，不增加 P2P 快照。 不存账号、业务结果或密文待发队列。真正断线仍由产品重连。
会话、账号、实例之间的关系

一个 runtime 实例处理多个桌面 target 和多个短期会话，不是“一个用户一个实例”。账号不是路由分片键；现有 DO 使用部署内共享的 Relay 对象。将来多实例扩容须显式保证会合两端落在同一个 owner，不能随机负载均衡后假定内存状态共享。
