# 开源自建与托管部署

日期：2026-11-04。目标是使用公开代码独立运行最小 Relay。
协议、客户端和 Bun 服务已实现；[源码启动与 TLS 配置](runtime.md)、
[Docker/Caddy](../deploy/docker/README.md)和[Cloudflare Tunnel](../deploy/cloudflare-tunnel/README.md)配置已提供。
产品端验收、正式域名部署和容器镜像发布仍待完成，验证范围见[部署记录](deployment-status.md)。

## 1. 默认运行范围

自建版与官方托管复用协议和转发逻辑。
一个 Bun runtime 即可承担会话会合、密文转发、背压限流和清理；
配置与 TLS 根据部署方式提供，不强制配置账号服务、业务数据库或独立管理后端。

设备身份和配对保存在桌面/App。runtime 只维护当前在线映射和临时会话，
重启使旧连接和临时凭据失效，客户端恢复会合；不要求建立设备登记库或备份 Relay 业务数据。

基础自建必须在未登录 Cherry 账号、无法访问 Cherry 私有 API、没有推送服务时运行。
未来部署者选择额外接入策略时，需要明确其外部依赖；不能暗中把策略故障降级为绕过校验。

## 2. R3 交付物

本次交付固定基础镜像 digest 的 Dockerfile、三种 Compose 入口（本机、Caddy、Tunnel）、
配置示例、公网 smoke 命令和容器 CI。Vercel 按当前决定暂缓，不将其列为已支持平台。
以下是完整 R3 验收目标，提供模板不代表全部已完成：

- 可独立构建的源码、锁文件、明确的许可证与第三方依赖说明。
- 对应固定源码版本的 amd64/arm64 镜像与 Compose 示例。
- 可选 Caddy/TLS 示例，以及接入已有反向代理的说明。
- 监听/公开入口、WS upgrade、代理超时、受信代理和资源限制配置。
- 健康检查、必要指标、日志脱敏、启动/排空/升级/回滚步骤。

默认启动路径只运行基础中转。CLI 登记、账号后台、数据库迁移、TURN 或推送网关都不作为安装步骤。
配置和证书按部署需要保存；停止服务不修改端点配对、密钥或业务数据。

## 3. 客户端使用与验收

使用流程为：启动服务 → 客户端选择并确认 Relay 入口 → 会合 → Noise 与桌面配对批准 → 业务访问。
邀请和已配对重连信息由端点管理；临时凭据不放入 URL 查询参数、日志或指标。

从干净环境验证公开构建，阻断 Cherry 账号/API/Relay/推送域名后仍需完成：

- 未登录 App 跨网扫码配对和配置导入，桌面仍负责批准。
- 已配对重连、服务重启、换网和前后台恢复，保留配对。
- 撤销桌面配对后拒绝业务访问，停止 Relay 后释放连接。
- 重复接入、错误凭据、慢消费者和资源耗尽时正确拒绝或关闭。

HTTP 健康检查、本地模拟 peer、真机配对和实际云部署分别记录。
每个公开支持的部署模板需有实际运行证据，不能只凭镜像构建通过宣布支持。

## 4. 可选能力

用户体系、企业策略和收费遵守[可选接入边界](saas-auth-integration-plan.md)，不改变独立运行能力。
免费托管可以使用同一个 runtime，并通过运行限制控制资源；是否免费由实际成本决定。

后台推送独立提供，见[性能与通知方案](performance-and-operations-plan.md#4-可选后台推送)。
部署者只能使用自己有权使用的推送凭据；官方 App 的推送若需官方网关，明确标为可选外部依赖。
缺少推送不影响前台连接，自建服务不获得官方推送私钥。

## 5. Workers + Durable Objects

需要托管 runtime、无需自备服务器时，可使用[独立 Workers/DO 部署](../deploy/cloudflare/README.md)。
它支持 WebSocket 休眠与必要状态恢复，保持账号和业务存储独立；需要更新客户端的收包回执支持。
每部署一个 DO，可容纳多个设备和会话，正式容量/费用仍需云端验收。
