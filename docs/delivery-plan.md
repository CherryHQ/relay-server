# Cherry Relay 实施顺序

日期：2026-11-04。协议、客户端和单实例 Bun runtime 已交付并完成本地验证。
按[架构范围](architecture.md)推进基础中转，不以账号接入、设备库或计费系统为前置。

## 1. 主线

| 阶段               | 工作                                                       | 完成条件                                                       |
| ------------------ | ---------------------------------------------------------- | -------------------------------------------------------------- |
| R1 协议与端侧流    | 二进制帧、ready、RelayStream、真实 Noise/WSS 及包构建      | 本仓库验证已完成；双端实际构建和运行仍需验证                   |
| R2 最小 runtime    | 临时会合、二进制转发、接入保护、背压、限流、关闭和健康检查 | 本地真实 socket 验证已完成；生产负载及云部署待验证             |
| 客户端接入         | 桌面流入口、App 连接 owner、Relay 候选与再次会合           | 复用现有身份和配对；direct 保留；重连不要求重新扫码            |
| R3 完整自建        | Bun 容器、TLS 示例、配置、排空、跨网产品验证               | 干净公开构建及 Electron/iOS/Android 配对、导入、重连和撤销通过 |
| 所选混合云 runtime | 平台生命周期与同会话寻址适配                               | 各自通过同一协议/资源用例及真实部署测试                        |

R1 的包验证见[首批记录](r1-implementation-status.md)，runtime 的实现与验证见[R2 记录](r2-implementation-status.md)。
客户端工作以 R2 会合契约为接口，刷新目标分支后复用已有管理器，不在另一仓库重复实现连接 owner。

runtime 已具备有界内存会合与转发，后续接入不以持久状态迁移、设备登记后台、管理 CLI 或全局配额账本为前置。

## 3. 发布证据

协议测试、产品联调、真机生命周期、云部署和性能结果分别记录。
R3 至少证明：未知远端身份被拒绝、配对由桌面批准、重启/换网可恢复、撤销后业务访问失败，
以及自建配置在没有官方账号/API/推送服务时仍可用。

每个发布产物对应固定源码、依赖和协议版本。
升级先停止新连接并有期限地排空；不兼容的客户端明确拒绝，回滚不删除端点配对和业务数据。
未做实际部署的 vendor 保持待验证，存在目录或模拟测试不代表支持。

## 4. 按需求增加的能力

- [用户策略接入](saas-auth-integration-plan.md)：需要账号权益时再实现，runtime 保持可独立运行。
- [后台推送](performance-and-operations-plan.md#4-可选后台推送)：独立模块，先具备业务状态恢复，再验证通知投递。
- P2P 数据直连：按上述方案验证 DataChannel 库；Tailcat 保留为备选，不同时建设两套后端。
- 音视频媒体：出现具体产品需求再设计；使用 DataChannel 不代表引入音视频。
- 数据库、跨实例 broker 或持久管理能力：只有明确需求和部署证据后再引入。

免费提供是可选运营策略。首版保留运行资源限制和成本观测，收费与套餐不进入交付依赖。
