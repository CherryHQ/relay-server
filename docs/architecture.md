# Cherry Relay 架构与范围

日期：2026-11-04。首版范围为最小 WSS runtime；已实现的包、Bun 服务与验证见[R2 记录](r2-implementation-status.md)。

## 1. 目标与职责

让无法直接互连的 Cherry Studio 桌面与 App 通过公网 WSS 交换密文字节。
客户端优先使用可达的 direct 路径，Relay 提供备用传输；通道内继续使用现有 Noise 和业务协议。

| 组件          | 负责                                             |
| ------------- | ------------------------------------------------ |
| 桌面          | 设备身份、配对批准、业务权限、任务执行和结果     |
| App           | 保存配对、选择连接路径、取消与重连、恢复业务状态 |
| Relay runtime | 让双方会合、转发字节、限制资源、清理失效连接     |

runtime 的基础运行独立于用户凭证服务。登录、租户、设备归属后台和套餐均不属于首版。
Relay 的连接能力不赋予桌面业务权限；同一账号也不自动获得桌面访问权。

## 2. 最小连接流程

1. 桌面连接所选 Relay，建立临时在线或会合入口。
2. App 使用客户端获得的会合信息连接同一个 runtime；runtime 检查会话凭据、资源容量及接入状态。
3. 双端的数据连接就绪，确认相同的 session、运行时代际、协议版本和限制，再交给 RelayStream。
4. 两端通过现有 remote-transport 完成 Noise 握手与配对/业务授权，Relay 原样转发密文。
5. 断开或过期后清理会话；重连建立新会话和 Noise 通道，业务恢复由客户端负责。

会合标识用于定位，不能凭公开标识抢占另一条连接。最小会话凭据应不可猜测、限定用途与有效期，
通过 TLS 连接传递并避免进入 URL、日志或指标。它们只保护会合过程，不要求建设账号许可服务。

配对关系及再次会合所需的信息保存在端点；已配对设备重连不应要求每次扫码。
当前 runtime 以桌面保存的随机入口密钥恢复在线映射，每次会合重新生成临时票据，见[控制协议](runtime.md#2-最小会合)。
桌面/App 的候选地址和持久化仍需产品接入，不预设长期设备注册 API。

## 3. 状态归属

首版 Bun runtime 使用有界内存保存在线映射、待接入会话、socket、短期凭据和收发计数。
它不建设 Relay 业务数据库，也不保存账号、设备档案、用户余额、业务结果或待重放密文。

每个会话由一个 runtime 实例负责。临时集合具有数量和期限限制；关闭操作只清理其所属会话，
旧回调不能关闭新连接或重复释放资源。重启后旧会话和临时凭据失效，由客户端重建在线映射和连接。
配置、TLS 证书按部署需要保存，不因此引入业务数据库。

选用支持休眠的运行环境时，适配器必须明确恢复必要连接状态，或主动关闭并让客户端重连。
这属于平台生命周期处理，不能声称仅有内存 Map 就能跨实例或跨休眠继续同一会话。

## 4. 数据与资源边界

业务数据使用二进制 DATA 帧，不转成 Base64 JSON；控制消息有大小和时限限制。
Relay 不解析 Noise、业务 RPC、命令回执或任务结果，也不自动重放数据。

现有帧、窗口和端侧队列值见[实现方案](implementation-plan.md#3-二进制帧与流控)。
runtime 还需要独立限制连接数、会合请求速率、待接入数量、转发速率和实例总缓冲，
并把原生 WebSocket 缓冲计入资源测量。达到容量时拒绝或结束相应会话，避免无限排队。

这些是运行保护。免费服务同样需要防滥用；资源计数无需演变成用户计费账本。
是否免费提供，根据实际出站流量、并发和运维成本决定。

## 5. 部署与后续能力

先实现单实例 Bun runtime 和完整[开源自建](open-source-deployment.md)，不依赖 Cherry 私有 API。
混合云仅适配运行时；同类 VM/容器使用同一镜像。
多实例部署首先解决同一会话的两端如何到达同一实例，见[混合云方案](hybrid-cloud-adapters.md)。

账号权益如有实际需求，再接[可选策略](saas-auth-integration-plan.md)，不让产品登录或数据库进入转发循环。
[后台推送](performance-and-operations-plan.md#4-可选后台推送)独立于数据通道，由桌面业务事件触发。
Tailcat/P2P、WebRTC/媒体、跨云迁移按明确需求单独验证，不作为本轮前置。

## 6. 当前证据与待验证项

两个包及 Bun runtime 已通过本地真实 Noise/WSS、会合/流控故障和打包消费者验证。
Electron/iOS/Android 接入、自建镜像、生产负载与实际云部署仍待完成。
二维码与候选地址必须基于当前两端协议扩展，不能按历史 QR v2 假设另造冲突版本。

下一步按[实施顺序](delivery-plan.md)交付会合与转发闭环。
连接故障后的恢复时间、容量和费用由实测给出，不预先承诺多云无感接管或生产 SLO。
