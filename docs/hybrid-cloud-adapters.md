# Relay runtime 混合云适配

日期：2026-11-04。混合云范围仅限 Relay runtime；用户凭证服务独立。
当前 Bun runtime 已通过本地真实 socket 验证，尚无任何云平台的生产部署验收。

## 1. 最小部署方式

先交付单实例 Bun runtime。相同容器运行在不同云上，复用协议和代码，主要适配部署、TLS、连接超时和资源配置。
客户端使用显式选择的 Relay 入口；同一数据会话的两端必须到达同一个负责该会话的实例。

多实例不能仅依赖普通随机负载均衡，分别给两个客户端设置粘性 cookie 也不能保证它们会合。
部署需要稳定地把同一会话送到同一实例，例如明确节点入口或平台提供的会话寻址能力；
采用哪种方式随实际部署验证，不提前建立全局路由目录、共享数据库或跨云 broker。

实例故障后结束旧流，两端重新会合并建立 Noise。不透明接管旧 socket，也不复用旧会话凭据。
跨 origin 切换需由客户端连接 owner 明确选择，旧入口的凭据不能随重定向发送给新入口。

## 2. 适配职责

| 边界       | 需要适配的内容                                    |
| ---------- | ------------------------------------------------- |
| 连接 API   | upgrade、二进制收发、接收器就绪、关闭事件         |
| 背压       | send 返回值、原生缓冲、排空通知或可验证的替代机制 |
| 生命周期   | 计时、空闲、进程退出、排空、平台回收或休眠        |
| 同会话寻址 | 两端进入同一个实例，错误入口明确失败              |
| 资源观测   | 连接、队列、字节、拒绝数、内存和平台限制          |

核心不直接导入 vendor SDK。平台特有入口在构建或启动时显式装配，客户端无需知道服务器使用哪个厂商。
用户凭证、组织结构、套餐和收费不属于 vendor 适配器契约。

## 3. 平台状态

首版 Bun 的在线映射和会话保存在有界内存，重启后失效，由客户端重连。
若选用休眠或事件驱动平台，适配器必须验证两种方式之一：

- 保存并恢复继续同一连接所必需的最小状态，包括角色、代际、计数和凭据消费结果。
- 结束不能安全恢复的会话，通知或允许客户端重建。

恢复不能重新开放已消费的凭据、错误返还发送窗口或拼接两次 Noise 流。
平台的最小恢复状态不等于设备档案或账号数据库；只有实际适配需要时才增加对应存储。
普通进程、休眠环境和短生命周期函数分别验收，不因 TypeScript 接口相同就宣称兼容。

## 4. 验证与成本

每个拟支持的运行环境都需验证：两端实际会合、二进制帧长度、慢读背压、原生缓冲、
取消/关闭、重复接入、实例退出及客户端重连。消息容量须覆盖 64 KiB DATA 加 24 字节头。
无法约束内部缓冲或保证及时关闭的平台，保持未支持状态。

Cloudflare、Vercel 或其他 vendor 只在确定采用后检查当前能力、实现 adapter 并做真实部署测试；
本方案不预先承诺其数据面可用，也不要求首版实现全部适配器。

测试记录连接驻留、实际出口流量、内部转发和平台调用次数。
数据热路径不远程查询账号或数据库；如增加 broker/代理跳转，需要额外说明它解决的问题、延迟与成本。
本机回环成功不代表跨云性能或费用已经可接受。
