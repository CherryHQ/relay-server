# Relay 性能、运维与后台推送

日期：2026-11-04。保留二进制传输、有界资源、自建交付和可选后台通知。
包与回环基线见[R1 记录](r1-implementation-status.md)，runtime 资源验证见[R2 记录](r2-implementation-status.md)。
生产容量和费用尚未验证。

## 1. 二进制数据路径

沿用已有 DATA/ACK/CLOSE 编码，单个 DATA 最多 64 KiB，固定头为 24 字节。
Noise 字节直接通过二进制 WebSocket 传递，不转为 Base64 JSON，不解析业务内容。
控制消息有大小限制；密文关闭 WebSocket 压缩。

`decodeFrame` 的 DATA payload 借用输入缓冲，保留时复制；发送方不得复用仍被异步写入引用的内存。
现有 RelayStream 复制调用方数据，处理 Uint8ArrayList 时逐块复制，避免额外拼出一个完整临时数组。

当前没有延时小帧合并或 ACK 批量策略。先保留无延迟基线；
只在测得事件数/CPU 收益且首字节、尾延迟满足预算时，再考虑有界合并。
不为凑满帧而等待首个结果，也不为实验增加生产 Base64 兼容路径。

## 2. 背压与资源保护

现有端侧窗口、队列和超时值以[实现方案](implementation-plan.md#3-二进制帧与流控)为准。
发送队列采用 2 MiB，是为了容纳现有 1 MiB 上传加密后的头/tag；接收和原生发送缓冲分别限制。
字节数和项数都要受控，细碎数据不能积累无限元数据。

runtime 已独立限制活动连接、upgrade 速率、会话数、每连接/实例消息和字节速率以及输出缓冲。
初始配置见[运行说明](runtime.md#3-运行限制与观测)，不据此宣称生产容量。
容量不足时拒绝新请求或结束受影响的会话，慢消费者不能阻塞其他会话。
IP 可用于粗限流，但不能把同一个 NAT 下的用户都当成同一个设备或业务身份。

原生缓冲、应用队列和在途窗口分别观测；某个队列的上限不等于进程 RSS。
Bun 非空发送返回 -1 表示已入队，不能重发；返回 0 表示失败，结束该流。
缺少可靠排空信号的平台必须实测缓冲与关闭行为，不能用空实现声称支持背压。

ACK 只返还流量窗口，不代表业务完成。伪造或越界 ACK 不能扩大资源占用。
断线后重新会合和建立 Noise，不重放旧密文；取消、超时和迟到回调共用幂等清理路径。

## 3. 测量与费用

现有 `bun run perf:baseline` 在同一进程中运行两端和回环 WSS 转发器，
每场景三轮、每轮预热 3 次并测量 20 次，覆盖小 JSON、32 KiB JSON 和 1 MiB 上传。
其 p99 接近样本最大值，只用于诊断；采样 RSS 不是独立服务峰值，不能据此判断云端成本低。

后续验证按所选实际运行环境记录源码、运行时、硬件、网络 RTT/带宽/丢包、载荷及并发：

| 场景           | 需要测量或证明                                            |
| -------------- | --------------------------------------------------------- |
| 小消息与持续流 | 首字节/尾延迟、CPU、分配、消息数和实际转发字节            |
| 高 RTT / 弱网  | 窗口占用、吞吐、重连和取消耗时                            |
| 慢读与恶意流量 | 队列/原生缓冲有界，健康会话仍可用，超限及时关闭           |
| 连接建立与回收 | 会合速率、拒绝数、RSS/FD、调度延迟；循环后无持续增长      |
| 手机生命周期   | Electron/iOS/Android 真机换网、休眠、锁屏、系统回收与耗电 |
| 所选云平台     | 同会话寻址、实例回收/休眠、连接驻留、出口流量及实际费用   |

比较优化前后时保持环境与负载一致，重复采样；正确性通过不表示性能提升。
生产默认容量来自实测，不把固定并发配方或本机耗时当成 SLO。

成本主要观测：计算与连接驻留、出站流量、代理/LB 和监控运维；
若新增跨云转发或可选通知，分别核算其开销。
免费服务仍需运行限额和防滥用；首版不建立用户余额、账期或原子预扣系统。
是否免费提供等真实部署数据具备后决定。

## 4. 可选后台推送

推送由桌面业务结果产生，作为独立能力交付。Relay 不解析密文，也不从断线或流结束推断任务完成。
手机后台断开不取消桌面任务；通知仅提示有更新，App 恢复后通过既有安全连接读取真实状态。

先核对现有业务通知/结果记录，复用其恢复能力；需要重试时采用有界 outbox、稳定事件 ID、过期与去重。
通知数据归通知模块，不因此给 Relay 转发核心增加持久数据层。

投递需验证来源和接收方关系；连接会合凭据不自动授予向任意手机推送的权限。
配对撤销、token 轮换、重复/乱序及过期消息均需验证。
provider 请求采用独立并发和重试上限，通知故障不得拖住转发。

首批内容只包含必要提示和事件定位符，不发送 prompt、模型输出、私有路径或访问凭据。
provider 接受不等于用户已收到或 App 一定被唤醒；不自动执行推送携带的命令或任意 URL。

自建无推送时仍支持前台连接。
使用自有 App 时可配置有权使用的 APNs/FCM 凭据；官方 App 如需官方网关，必须显式启用并说明外部依赖。
官方推送私钥不下发自建服务。具体 provider、网关和持久队列仅在该功能实际实施时增加。

## 5. 自建与后续实验

基础交付见[自建方案](open-source-deployment.md)：单实例 Bun、TLS、资源配置、健康检查与排空，不要求数据库或登记 CLI。
升级和故障通过有界重连恢复访问，端点负责保留配对和业务恢复信息。

[P2P 数据直连](p2p-implementation-plan.md)先验证现成 DataChannel 库，测实际绕过中转的流量、
原生桥接开销、回退、功耗和部署成本；Tailcat 保留为备选。DataChannel 只承载数据，不要求媒体功能。
能力归端侧 `remote-transport/p2p`；首版先建立已认证的 Relay 通道承载加密信令，
新 P2P 流再次完成 Noise/授权和切换确认后释放旧数据通道；失败沿用 Relay，提交结果不确定则重连。
测量必须计入额外建连和两次 Noise 的成本，以及旧流与候选并存的缓冲峰值。
runtime 保持纯转发，不增加信令或选路状态。客户端配置已有 STUN 辅助打洞，自建服务可选；
TURN 和音视频按后续实际需求交付，不加入基础运行依赖。
